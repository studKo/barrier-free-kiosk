# 3D 키오스크 (Three.js + HTML UI) 개발 가이드 및 기준

본 문서는 프로젝트 진행 중 겪은 시행착오를 바탕으로, 동일한 이슈의 재발을 막고 향후 개발 시 명확한 기준을 세우기 위해 작성되었습니다.

## 1. 3D 카메라 줌(Zoom) 시점 보정 기준
**[문제 상황]**
줌 인(확대) 기능 구현 시 카메라의 `Z축(앞뒤)` 거리만 당겼을 경우, 고정된 대상(Target)을 내려다보게 되어 키오스크 윗면만 크고 평면이 뒤틀린 듯한(Top-down) 왜곡된 뷰가 연출됨.

**[해결책 및 기준]**
확대(Zoom in) 로직을 짤 때는 카메라가 타겟에 가까워지는 것에 비례하여 카메라의 `Y축(높이)`과 카메라가 바라보는 타겟의 `LookAt Y축` 높이도 함께 낮춰야 함.
*   **기준 1:** 완전히 줌 인 했을 때는 카메라의 Y 좌표와 Target의 Y 좌표를 수평(일치)에 가깝게 보간(Lerp)하여 '정면 뷰'를 유지할 것.
*   **기준 2:** 줌 레벨 변하는 동안 `THREE.MathUtils.lerp()`를 사용하여 자연스럽게 시선이 수평을 찾아가도록 설계.

## 2. 2.5D 및 대형 비율 UI 레이아웃 기준 (CSS 레이어링)
**[문제 상황]**
키오스크 화면 비율을 강제로 키우기 위해 CSS `flex: 4` 등 중앙 패널 영역을 확장했을 때, 좌/우측의 기능성 UI(퀘스트 창, 버튼 등)가 비정상적으로 찌그러지거나 잘리는 현상 발생.

**[해결책 및 기준]**
*   **기준 1 (HTML/CSS):** 좌우 패널의 모양과 가독성 유지를 위해 전체 그리드나 플렉스 비율(예: `1 : 2 : 1`)은 함부로 건드리지 않고 원본을 유지함.
*   **기준 2 (3D Camera):** 렌더 패널 내에서 객체를 크게 보이고 싶다면 CSS 영역을 강제 확장하지 말고, **Three.js 카메라 자체를 피사체에 바짝 당기는 방식(`position.z` 축소)**을 사용함.
*   **기준 3 (평면감 2.5D):** 완전한 3D 입체감보다 2.5D 형태의 명확한 화면이 필요할 때는 카메라의 **시야각(FOV)을 좁혀서(예: 45도 이하)** 원근 왜곡을 줄여 화면을 평평하게 만듦.

## 3. UI 객체(3D Mesh)의 화면 표시 및 스폰 기준
**[문제 상황]**
줌 레벨이 다를 때 거리에 의존해 카드를 스폰하면, 카메라 바깥으로 카드가 잘리거나 안 보이는 문제 발생.
처음부터 화면에 불필요한 지시 화살표가 노출되어 사용자 시선를 빼앗음.

**[해결책 및 기준]**
*   **가시성 확보:** 3D 상호작용 물체(신용카드 등)는 특정 객체 기준이 아닌 **"카메라와 대상 사이의 고정된 절대 월드 좌표(Mid-air)"**에 띄워 줌 상태와 관계없이 항상 화면 중앙 근처에 배치되게 할 것.
*   **순차적 노출:** 사용자 시야를 유도하는 에셋(빨간 화살표 등)은 초기 로드 시 반드시 `visible = false`로 숨김 처리. **해당 액션이 필요한 단계(예: 결제 단계 진입)에 도달했을 때만 점등**시켜 혼란을 방지할 것.

## 4. 로컬 환경 테스트 (Localhost) 기준
**[문제 상황]**
개발 중 터미널(Dev server)이 중지되거나 다른 포트에서 실행되어 빈 화면 또는 연결 거부(Connection Refused) 에러 발생. 기기 내 로컬호스트 접근 문제.

**[해결책 및 기준]**
*   Vite 서버 등이 `npm run dev -- --host 0.0.0.0` 상태로 정상 작동하고 있는지 먼저 점검할 것.
*   에이전트 또는 브라우저 봇 동작 전 서버 활성화 여부(Playwright 포트 접근 등)를 필수로 선행 확인할 것.
*   와이파이(망)와 무관하게 `localhost` 접근이 가능해야 하나, 프로세스 중복 실행 여부를 체크해 포트가 점유되었는지 여부를 관리할 것.
